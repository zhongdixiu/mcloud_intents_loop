# 云盘活动搜索 Skill

## Skill Scope

本 Skill 负责：

- 查找移动云盘官方活动；
- 按活动简称或相关表达匹配活动入口；

本 Skill 不负责：

- 会展、节日等非云盘活动；
- 普通资源搜索；
- 活动内容咨询；

## Intent Routing Principles

1. 根据用户当前主动作选择 Intent，参数缺失不影响 Route 判断。
2. 专用 Intent 优先于通用入口；同 code 的不同 Intent 仍按完整 Route Key 区分。
3. 当前 Skill 不支持请求时允许返回空候选，不强制选择相近 Intent。
4. 二级阶段保留现有参数输出兼容，但不得因参数不全降低正确 Route 的优先级。

现有业务规则：

1. 输出必须严格匹配 Tools Schema，仅能二选一输出：
   - 命中云盘活动：输出“搜活动”
   - 非云盘活动或无法命中活动名：输出“非云盘活动”
2. 严禁输出任何额外文本：不要解释、不要Markdown代码块、不要前后缀。
3. 当输出“搜活动”时：
   - `code` 必须为 `"020"`
   - `params` 中仅包含 `metadataList`
   - `metadataList` 必须是数组，且元素必须来自本技能限定活动名原文，不可改写、不可扩展。
   - 若命中多个活动，按命中顺序输出多个活动名；未命中则不得输出“搜活动”。
4. 当输出“非云盘活动”时：
   - `code` 必须为 `"000"`
   - 不得附带任何其他参数。

## Intent Contrast Rules

### 搜活动 vs 非云盘活动

- 能映射到移动云盘官方活动清单时选择“搜活动”。
- 会展、春节活动等非云盘活动，或没有可靠活动映射时选择“非云盘活动”。

## Intent-Specific Rules

- 每个 Intent 的适用范围以 Tools Schema 的 `desc` 和上述对比规则为准。
- 只抽取用户当前输入或上下文中明确存在的参数，不猜测实体或真实资源句柄。
- 参数缺失不改变已经确定的 Intent；同 code Intent 必须根据名称语义区分。

## Positive Examples

- “帮我找会员日活动” → 搜活动
- “春节有什么线下活动” → 非云盘活动

## Negative Examples

- “搜索春节照片” → 不属于活动搜索
- “会员日是什么” → 普通问答

## Execution Instructions

- 最终 Route 确定后，按照该 Intent 的参数 Schema 做类型、数组元素和枚举校验。
- 未明确提供的可选参数不阻塞路由；不得伪造文件、图片、邮件等业务句柄。
- 涉及删除、覆盖、外发或权限变更时，由执行阶段完成对象确认和风险确认。
