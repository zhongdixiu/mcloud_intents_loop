# 相册工具 Skill

## Skill Scope

本 Skill 负责：

- 影集创作；
- 回忆故事；
- 美图相册；
- 生成回忆相册；
- 照片直播；

本 Skill 不负责：

- 单张图片生成或编辑；
- 仅搜索已有图片；
- 普通文件浏览；

## Intent Routing Principles

1. 根据用户当前主动作选择 Intent，参数缺失不影响 Route 判断。
2. 专用 Intent 优先于通用入口；同 code 的不同 Intent 仍按完整 Route Key 区分。
3. 当前 Skill 不支持请求时允许返回空候选，不强制选择相近 Intent。
4. 二级阶段保留现有参数输出兼容，但不得因参数不全降低正确 Route 的优先级。

现有业务规则：

1. 生成回忆相册 vs 回忆故事 vs 影集创作：
    - 当用户给出明确的任务，使用某人/某时/某地的照片制作回忆相册/影集/合集时，输出“生成回忆相册”
    - 当用户说“生成影集”/“制作影集”/“做成合集”等诉求时，只要提供了可用于搜图的线索（如人物、时间、地点、事件、场景、拍摄对象、照片特征等），输出“生成回忆相册”
    - 仅当用户没有提供任何图片来源或筛选线索，只表达“做影集/做合集”意图时，输出“影集创作”
    - 当用户未给出明确任务且意图是故事创作时：
        - 输入“我的故事”/“创建回忆故事”时，输出“回忆故事”
    - 示例：
        - 整理我的图片做成回忆故事 → "生成回忆相册"
        - 把我和朋友的合照生成影集 → "生成回忆相册"
        - 创建我的故事 → "回忆故事"
        - 创建我的影集 → "影集创作"
        - 帮我做个影集 → "影集创作"
2. “生成回忆相册”参数抽取规则：
    **2.1 keyword（图片关键词）**：
        - 提取用户要搜的核心对象或主题，如人物、事件、活动、地点、场景、物品（如“宝宝”“毕业典礼”“海边”）。
        - 忽略泛词，如“图片”“照片”“相册”“回忆”等不具检索意义的词。
        - 多个关键词并列时，按原语义合并为短语或保留多个关键词（如“我和妈妈的旅行照”可抽取为“我和妈妈”“旅行”）。
    **2.2 timeList（搜索时间范围）**：
        - 提取时间表达，如“去年”“上个月”“2024年”“春节期间”“大学毕业那年”。
        - 多时间条件按出现顺序放入列表，如“去年暑假到国庆”→ ["去年暑假", "国庆"]。
        - 未提及时间则留空列表。
    **2.3 searchRule（搜索规则）**：
        - 出现强约束词（“只要/仅要/必须/限定”）时，抽取为“精准”。
        - 出现宽泛词（“相关/类似/差不多/都可以”）时，抽取为“宽松”。
        - 同时包含多个条件但未指明强弱时，抽取为“综合”。
        - 未明确规则时，默认“综合”。
    **2.4 count（图片张数）**：
        - 提取数量表达，如“10张”“二十张左右”“至少30张”“来5-8张”。
        - 区间数量取上限（如“5-8张”→ 8）；“至少N张”取 N；“N张左右”取 N。
        - 未提及数量时不填该参数。
    - 参数抽取示例：
        - “帮我用去年在三亚拍的宝宝照片做个回忆相册，来20张” →
          keyword: "宝宝", timeList: ["去年"], searchRule: "综合", count: 20
        - “只要我和爸爸的合照，春节期间的，5-8张” →
          keyword: "我和爸爸合照", timeList: ["春节期间"], searchRule: "精准", count: 8
        - “找一些和毕业相关的照片做回忆相册” →
          keyword: "毕业", timeList: [], searchRule: "宽松"

## Intent Contrast Rules

### 生成回忆相册 vs 影集创作

- 提供人物、时间、地点、事件等选图线索并要求制作合集时，选择“生成回忆相册”。
- 仅要求进入或使用影集制作、没有选图线索时，选择“影集创作”。

### 回忆故事 vs 生成回忆相册

- 明确创作“我的故事/回忆故事”时选择“回忆故事”。
- 要求筛选照片后制作相册或影集时选择“生成回忆相册”。

## Intent-Specific Rules

- 每个 Intent 的适用范围以 Tools Schema 的 `desc` 和上述对比规则为准。
- 只抽取用户当前输入或上下文中明确存在的参数，不猜测实体或真实资源句柄。
- 参数缺失不改变已经确定的 Intent；同 code Intent 必须根据名称语义区分。

## Positive Examples

- “用去年三亚的宝宝照片做回忆相册” → 生成回忆相册
- “帮我做个影集” → 影集创作

## Negative Examples

- “生成一张海报” → 图像与视觉工具
- “找去年的照片” → 云盘搜索

## Execution Instructions

- 最终 Route 确定后，按照该 Intent 的参数 Schema 做类型、数组元素和枚举校验。
- 未明确提供的可选参数不阻塞路由；不得伪造文件、图片、邮件等业务句柄。
- 涉及删除、覆盖、外发或权限变更时，由执行阶段完成对象确认和风险确认。
