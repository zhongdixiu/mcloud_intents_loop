# 圈子工具 Skill

## Skill Scope

本 Skill 负责：

- 圈子首页；
- 圈子动态发布；
- 创建圈子；
- 搜索圈子；

本 Skill 不负责：

- 共享群和家庭云；
- 普通云盘资源搜索；
- 朋友圈图片生成；

## Intent Routing Principles

1. 根据用户当前主动作选择 Intent，参数缺失不影响 Route 判断。
2. 专用 Intent 优先于通用入口；同 code 的不同 Intent 仍按完整 Route Key 区分。
3. 当前 Skill 不支持请求时允许返回空候选，不强制选择相近 Intent。
4. 二级阶段保留现有参数输出兼容，但不得因参数不全降低正确 Route 的优先级。

现有业务规则：

1. 只要用户在“圈子/群”语境下表达“找某类圈子、要一个某主题圈子、问某圈子入口在哪”，优先触发`搜索圈子`。
2. 命中以下表达时，强制触发`搜索圈子`，不要触发`圈子首页`或`创建圈子`：
   - “麻烦找出漫画圈子入口在哪里”
   - “电影的圈子来一个”
   - 同类表达：`<主题词> + 圈子 + 来一个/找一下/入口在哪/有没有`
3. `圈子首页`仅在用户明确要“打开圈子主页/进入圈子首页/去圈子主页面”且未给出任何主题词时触发。
4. `创建圈子`仅在用户明确有创建意图时触发，如“创建/新建/建一个圈子”，不包含“找/搜/来一个/有没有/入口在哪”等检索意图词。
5. 触发`搜索圈子`时，`metadataList`提取主题词、圈名、人名等检索关键词。

## Intent Contrast Rules

### 搜索圈子 vs 圈子首页

- 带主题、圈名、成员或“找一个圈子”语义时选择“搜索圈子”。
- 仅明确进入圈子主页且没有检索条件时选择“圈子首页”。

### 搜索圈子 vs 创建圈子

- “找、搜、有没有、来一个”表示检索；“创建、新建、建一个”才表示创建。

## Intent-Specific Rules

- 每个 Intent 的适用范围以 Tools Schema 的 `desc` 和上述对比规则为准。
- 只抽取用户当前输入或上下文中明确存在的参数，不猜测实体或真实资源句柄。
- 参数缺失不改变已经确定的 Intent；同 code Intent 必须根据名称语义区分。

## Positive Examples

- “找一个漫画圈子” → 搜索圈子
- “创建一个摄影圈” → 创建圈子

## Negative Examples

- “新建家庭共享群” → 社交与共享
- “搜云盘里的漫画” → 云盘搜索

## Execution Instructions

- 最终 Route 确定后，按照该 Intent 的参数 Schema 做类型、数组元素和枚举校验。
- 未明确提供的可选参数不阻塞路由；不得伪造文件、图片、邮件等业务句柄。
- 涉及删除、覆盖、外发或权限变更时，由执行阶段完成对象确认和风险确认。
