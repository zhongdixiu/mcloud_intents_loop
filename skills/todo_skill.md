# AI待办 Skill

## Skill Scope

本 Skill 负责：

- 添加待办；
- 确认待办；
- 修改待办；
- 查询待办；

本 Skill 不负责：

- 普通日程咨询；
- 笔记记录；
- 未表达待办或提醒语义的普通事项；

## Intent Routing Principles

1. 根据用户当前主动作选择 Intent，参数缺失不影响 Route 判断。
2. 专用 Intent 优先于通用入口；同 code 的不同 Intent 仍按完整 Route Key 区分。
3. 当前 Skill 不支持请求时允许返回空候选，不强制选择相近 Intent。
4. 二级阶段保留现有参数输出兼容，但不得因参数不全降低正确 Route 的优先级。

现有业务规则：

1. 参数抽取通用规则：
    - 所有参数字段默认输出数组；若用户未明确提及该信息，统一返回空数组 `[]`。
    - 对于模糊描述不做强行提取，例如时间类"我结婚的时候"等，不作为结构化参数输出。
    - `timeList` 遇到连续时间范围时必须合并为一个完整片段，不得拆分为多个时间点；如"这周"应提取为["本周一至本周日"]，"最近7天"应提取为["最近7天"]。
    - 在 `AI待办修改(041003)` 的时间修改场景中，`timeList` 优先抽取被修改的原时间；例如"如果把昨天的会议时间待办改成今天下午"，应提取 `["昨天"]`。
    - `AI待办添加(041001)` 仅抽取 `todoItemList`，不抽取 `timeList`；即使用户query中包含时间表达，也不得在该工具参数中输出时间字段。
2. 待办事项(todoItemList)参数抽取说明：
    - 待办事项抽取是列表，支持抽取多个待办事项，最多20个待办事项，超出后舍弃。
    - 待办事项抽取没有顺序之分，按照用户上下文抽取出正确的待办事项即可。
    - 在多轮对话场景中，若用户通过序号引用待办（如"第一个"、"第二个"），需根据上下文确定具体的待办事项内容并提取。
    - 未提及则返回 `[]`。
3. 意图区分规则：
    - AI待办添加(041001)：用户需要添加待办。
    - AI待办确认(041002)：用户确认添加/确认更新的待办事项。重要规则：AI待办确认需要在多轮对话中触发，即上轮对话中用户触发AI待办添加/AI待办修改后才能触发。
    - AI待办修改(041003)：用户对已有待办事项不满意或需要补充修改。
    - AI待办查询(041004)：用户查询已添加的待办事项。
4. 意图匹配确认规则：
    - 规则1：假如当前 query 不存在触发词（提醒xxx、xxx待办、xxx事项、xxx待办事项、xxx创建待办、添加待办xxx、xxx提取到待办、~~todo、~~todolist、~~To-do），则本 Skill 返回空候选。
    - 规则2：AI待办确认(041002)需要明确上文存在AI待办添加(041001)或者AI待办修改(041003)的调用记录才能使用，否则不允许使用该工具。

## Intent Contrast Rules

### AI待办添加 vs AI待办确认

- 新建提醒或事项时选择“AI待办添加”。
- 只有上一轮为添加或修改、当前轮明确确认时才选择“AI待办确认”。

### AI待办修改 vs AI待办查询

- 改动已有事项选择“AI待办修改”；询问现有待办选择“AI待办查询”。

## Intent-Specific Rules

- 每个 Intent 的适用范围以 Tools Schema 的 `desc` 和上述对比规则为准。
- 只抽取用户当前输入或上下文中明确存在的参数，不猜测实体或真实资源句柄。
- 参数缺失不改变已经确定的 Intent；同 code Intent 必须根据名称语义区分。

## Positive Examples

- “提醒我周五提交报告” → AI待办添加
- “我今天有什么待办” → AI待办查询

## Negative Examples

- “记录一篇笔记” → 笔记工具
- “会议安排是什么” → 普通问答

## Execution Instructions

- 最终 Route 确定后，按照该 Intent 的参数 Schema 做类型、数组元素和枚举校验。
- 未明确提供的可选参数不阻塞路由；不得伪造文件、图片、邮件等业务句柄。
- 涉及删除、覆盖、外发或权限变更时，由执行阶段完成对象确认和风险确认。
