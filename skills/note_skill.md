# 笔记工具 Skill

## Skill Scope

本 Skill 负责：

- 普通笔记；
- 语音笔记；
- 笔记搜索；
- AI 笔记；
- 会议录音；
- 录音导入；

本 Skill 不负责：

- 待办事项管理；
- 普通文档搜索；
- 会议纪要生成；

## Intent Routing Principles

1. 根据用户当前主动作选择 Intent，参数缺失不影响 Route 判断。
2. 专用 Intent 优先于通用入口；同 code 的不同 Intent 仍按完整 Route Key 区分。
3. 当前 Skill 不支持请求时允许返回空候选，不强制选择相近 Intent。
4. 二级阶段保留现有参数输出兼容，但不得因参数不全降低正确 Route 的优先级。

现有业务规则：

- 若用户未明确说明要打开/创建哪种笔记类型，或说明打开的是云盘笔记，则默认执行「创建普通笔记」。
- 易混淆意图判定补充：
  - 询问笔记入口/位置且无其它限制时，按创建意图处理，统一执行「创建普通笔记」，包括但不限于：`笔记功能在哪里`、`笔记在哪打开`、`怎么进入笔记`、`笔记入口在哪`、`帮我查看笔记`。
  - 明确表达“语音记录 + 转文字 + 会议速记”场景时，统一执行「创建语音笔记」，包括但不限于：`记录会议对话`、`请打开语音速记，我现在要记录会议内容`、`帮我把这个录音转成文字记录`、`记录一下这个会议录音`、`打开会议速记的功能`、`语音转文字`。

## Intent Contrast Rules

### 创建普通笔记 vs 创建语音笔记

- 普通记录、笔记入口或未指定类型时选择“创建普通笔记”。
- 明确录音转文字、语音速记时选择“创建语音笔记”。

### 搜笔记 vs 创建普通笔记

- 明确查找已有笔记时选择“搜笔记”；仅查看笔记入口按创建普通笔记处理。

## Intent-Specific Rules

- 每个 Intent 的适用范围以 Tools Schema 的 `desc` 和上述对比规则为准。
- 只抽取用户当前输入或上下文中明确存在的参数，不猜测实体或真实资源句柄。
- 参数缺失不改变已经确定的 Intent；同 code Intent 必须根据名称语义区分。

## Positive Examples

- “记录会议对话并转文字” → 创建语音笔记
- “找上周的会议笔记” → 搜笔记

## Negative Examples

- “提醒我开会” → AI待办
- “生成会议纪要” → 办公效率与创作

## Execution Instructions

- 最终 Route 确定后，按照该 Intent 的参数 Schema 做类型、数组元素和枚举校验。
- 未明确提供的可选参数不阻塞路由；不得伪造文件、图片、邮件等业务句柄。
- 涉及删除、覆盖、外发或权限变更时，由执行阶段完成对象确认和风险确认。
