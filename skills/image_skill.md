# 图像与视觉工具 Skill

## Skill Scope

本 Skill 负责：

- 图片生成；
- 图片编辑与修复；
- 图片识别与问答；
- AI 相机；
- 头像和表情包创作；

本 Skill 不负责：

- 仅搜索已有图片；
- 相册影集创作；
- 普通图片浏览；

## Intent Routing Principles

1. 根据用户当前主动作选择 Intent，参数缺失不影响 Route 判断。
2. 专用 Intent 优先于通用入口；同 code 的不同 Intent 仍按完整 Route Key 区分。
3. 当前 Skill 不支持请求时允许返回空候选，不强制选择相近 Intent。
4. 二级阶段保留现有参数输出兼容，但不得因参数不全降低正确 Route 的优先级。

现有业务规则：

1. 生成/处理主动作优先：
    - 当用户主动作是生成、创作、做、画、编辑、处理、配文、识别、翻译、鉴伪、修复图片或视觉内容时，应使用本技能，而不是云盘搜索。
    - 历史指代、素材来源、时间范围等通常只是处理对象或限定条件；只要当前主动作是生成或处理视觉内容，不应改判为资源搜索。
    - 历史搜索结果只能帮助理解主体或素材来源，不代表真实图片句柄已经存在，也不要伪造`image`参数。
2. 当用户要求根据文本描述生成新的图片、照片、插画、海报、表情包等视觉内容，且没有要求使用已有图片做处理时，输出"文生图"工具。
3. 当用户要生成头像或处理头像时，除非特别说明使用某个工具，否则都输出"AI头像"工具。
    - 示例：
        - "给我的头像加上动漫效果" -> "AI头像"
        - "用图片动漫化工具帮我生成一个动漫头像" -> "图片动漫化"
4. 当用户针对老照片进行处理时，除非特别说明使用某个工具，否则输出"老照片修复"工具。
5. 当用户要求整理图片且包含**将素材组合**的意图时，应交给相册工具的“生成回忆相册”；若没有匹配本 Skill 的图片生成、处理或识别动作，允许返回空候选。
6. "AI相机"类意图：
    - 当用户明确要求翻译图中文字时，输出“AI相机拍照翻译”。
    - 当用户要求“答疑/答题”时，输出“AI相机拍照解题”。
    - 当用户未明确表明识图目的、无法确定需要讨论的主题时，输出“AI相机拍照问答”。
7. AI写真 vs AI相机：
    - 当用户输入"妙云相机"时，输出"AI写真"。
8. 当用户需要图片配文、描述图片，或明确要求在图片上添加文字（如“给这张图片添加文字”“给这张照片加上一句激励人心的话”“想让这张图带有文字”）时，输出“AI相机拍照问答”。
9. 当用户需要提取图片内容时，输出“AI相机拍照问答”。
10. "AI改图"为图像处理类兜底意图。
11. 当用户仅输入“图片配文”时，输出"AI相机拍照问答"，且不抽取`<image>`参数。

## Intent Contrast Rules

### 文生图 vs AI改图

- 仅根据文本创建新图片时选择“文生图”。
- 对已有图片做未被专用 Intent 覆盖的编辑时选择“AI改图”。

### AI头像 vs 图片动漫化

- 头像生成或头像处理默认选择“AI头像”；明确指定动漫化工具时选择“图片动漫化”。

### 图片处理 vs 图片搜索（跨 Skill）

- 生成、编辑、识别和修复由本 Skill 承接；仅查找已有图片进入云盘搜索。

## Intent-Specific Rules

- 每个 Intent 的适用范围以 Tools Schema 的 `desc` 和上述对比规则为准。
- 只抽取用户当前输入或上下文中明确存在的参数，不猜测实体或真实资源句柄。
- 参数缺失不改变已经确定的 Intent；同 code Intent 必须根据名称语义区分。

## Positive Examples

- “生成一张夏日海报” → 文生图
- “把这张老照片修复一下” → 老照片修复

## Negative Examples

- “找宝宝照片” → 云盘搜索
- “把照片做成回忆影集” → 相册工具

## Execution Instructions

- 最终 Route 确定后，按照该 Intent 的参数 Schema 做类型、数组元素和枚举校验。
- 未明确提供的可选参数不阻塞路由；不得伪造文件、图片、邮件等业务句柄。
- 涉及删除、覆盖、外发或权限变更时，由执行阶段完成对象确认和风险确认。
